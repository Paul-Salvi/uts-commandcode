# input-search
- When providing a search input for a data table, maintain two state variables: one for the controlled input value (updated on every keystroke/`onChange`) and one for the "committed" search query (updated only on Enter key or Search button click). Pass only the committed search value to the data-fetching query — this avoids triggering a new server request on every keystroke while still showing the user their live typing. Confidence: 0.80

# state-management
- For payment/checkout flows that involve opening an external tab, use in-memory React state (useState + useRef for polling intervals) rather than sessionStorage — sessionStorage persists across tabs and can be read by other scripts on the same origin. If refresh-safety is needed, use sessionStorage keyed by a unique session ID and clear it on explicit reset, but default to in-memory state for better security isolation. Confidence: 0.80
